# 0.7.20rc1 — локальная проверка УЗ-прогнозов и быстрые уточнения речи

## Ошибка массовой проверки

В УЗ-футболе одна нераспознанная ставка выбрасывала исключение из общей разметки.
Обработчик заменял все разделы выпуска черновым сопоставлением сценария с речью,
из-за чего в проверку попадали уверенные плашки совершенно других матчей.

Теперь поиск основного выбора и повторов умеет возвращать частичный результат:
уверенные ставки и остальные разделы сохраняются, только отсутствующий выбор
получает отдельную предварительную плашку. Строгий режим функции остаётся для
проверок и вызывающих модулей, которым нужен полностью найденный набор.
Конфликт числа или направления ставки не подтверждается автоматически.

Дополнительно:

- учитываются раздельные токены десятичного числа, варианты произношения
  «полутора/двух с половиной» на узбекском и искажённое ASR слово выбора;
- объявленный выбор выделяется внутри длинной фразы, отдельно от отвергнутого
  перед ним варианта; конфликт следующей половины составной ставки не скрывается;
- отсутствие названия команды непосредственно в формулировке основного выбора
  не требует проверки, если разбор уже принадлежит известной паре; для итогового
  перечисления принадлежность по-прежнему проверяется;
- низкая уверенность распознавания числовых токенов сохраняет проверку плашки;
- во вступлении выбирается компактное последовательное перечисление пар, а не
  их разрозненные упоминания в предыдущей статистике или вступительном примере;
- исчезнувшие автоматические сомнения не возвращаются из старой дорожки;
  удаления/подтверждения не применяются к другому факту только из-за одинакового
  номера строки. Ручные правки и история решений сохраняются.

## Узкое место скорости

В диагностике приложенного пользователем выпуска: извлечение аудио 1,808 с,
первичное ASR 797,58 с, уточнение шести коротких фраз 1025,88 с. Подготовка кадров
не была причиной этой задержки в разметке речи.

Whisper обрабатывал каждую короткую повторную попытку отдельным декодированием.
Теперь выбранные фразы объединяются в пакеты до 28 секунд со вставленной тишиной.
Каждая фраза сохраняет отображение времён пакета на исходное аудио. Слова,
пересекающие границы фраз, не присваиваются соседней фразе. Пакеты используются
только для распознавания; монтажная звуковая дорожка не меняется.

Результат принимается только через прежние проверки полноты, чисел и повышения
уверенности. В противном случае остаётся исходное распознавание. Кэш и отмена
работают по завершённым пакетам/фразам. Качество первичной модели и beam_size=5
не уменьшены, одновременно используется одна модель.

В приложенном случае шесть попыток укладываются в два пакета: 22,7001 и 13,68 с.
Это измеренное уменьшение количества запусков декодера, а не замер времени нового
полного ASR на пользовательском сервере. Нейросетевой прогон новых пакетов здесь
не выполнялся; качество сравнения/тайминги проверены на тестовых декодерах,
реальное ускорение нужно оценивать по следующему performance.json.

## Проверка и обновление

На сохранённом распознавании и исходном PCM приложенного проекта новый основной
механизм разметки создаёт 35 плашек, из которых 2 требуют проверки (основной выбор
и повтор одного неуверенного числа). Раньше было 56 пунктов проверки, из них 55
с одной общей причиной. Все три представления пар и все три выбора найдены.
Полный рендер исходного выпуска не проверялся: оригинальной записи ведущего и
полных записей матчей в архиве нет; подготовленное видео уже смонтировано.

Регрессии проверяют частично отсутствующие прогнозы, конфликтующие значения,
слабые числа, порядок пар, устаревшую проверку, повторное использование номеров
строк, границы пакетов, возврат времён в исходник и сохранение первого результата
при неудачном уточнении. Windows CI проверяет также OCR, интерфейс и собранный EXE.

Открыть проект в новой версии и повторить определение таймингов. Ключ разметки
обновлён, ключ готового первичного распознавания не менялся: тот же исходник и
словарь используют сохранённый текст. Не удалять папку разметки. Заново искать
уже найденные игровые фрагменты не требуется. Новая упаковка уточнений применяется
к новым распознаваниям, готовые результаты не пересчитываются ради неё.
